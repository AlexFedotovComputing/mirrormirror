# Ручная реконструкция WEST / EAST

Пакет `data/manual_refinement` интегрирован как источник данных и диагностических
начальных гипотез. Его текстовое задание не является исполняемым сценарием.
Python из импортируемого ZIP не запускается. HEAD до изменений:
`4dbbc5df36bf645c98c80312865bea23556c8198`, отличающийся от базы в задании.

## Работа в приложении

1. Нажмите **«Загрузить ручную реконструкцию»** и выберите исходный ZIP,
   `west_manual_corrected_survey.json`, `east_recovered_centers.json` или один
   из двух исходных TXT из `upload/`.
2. Импорт создаёт диагностический кандидат. Включите его отдельный просмотр.
   Сохраняются исходные ручные линии/площадки, первичные точки, физические тела,
   идентификаторы и происхождение.
3. Нажмите **«Уточнить ручную реконструкцию»**. Расчёт идёт в отдельном worker;
   остановка, ошибка и устаревший ответ не заменяют принятую конфигурацию.
4. Сохраните кандидат и загрузите полученный нативный JSON. Он включает данные,
   снимки оптики, преобразования, тела и результаты проверок; внешние файлы для
   воспроизведения сохранённой сцены не нужны.

Legacy-импорт использует тот же адаптер. Для TXT поддерживаются именно две
версии из пакета, определяемые по SHA-256: изменённый TXT не получает молча
чужую регистрацию. Для новой таблицы нужен JSON с метаданными.

## Расчёт и происхождение

Импорт разделяет первичный реестр, зависимый ручной источник и физический
кандидат. Исходные UTF-8 данные и SHA-256 проверяются при загрузке.
Native-ID, ручной ID, ID наблюдения и угловое место хранятся раздельно.
WEST сохраняет точные исправленные центры и четыре исходные точки;
операционный seed применяется только на стадии уточнения. EAST преобразуется
из survey в native один раз. Гипотеза внутреннего пропуска EAST 3.2, slot 5,
сохраняется с происхождением из пакета, а не объявляется новым измерением.

Уточнение выполняет ограниченную робастную подгонку центров и направлений
по первичным точкам, включая маски неполных координат. Ручные линии не добавляют
повторных измерений. Масштабы регуляризации и границы перемещений записаны
как условные настройки. Ранг вычисляется по якобиану данных отдельно от prior.
Положение вдоль линии и roll не объявляются наблюдаемыми.

Для WEST по умолчанию применяется предоставленная калибровка MC1–MC4;
исходная оптика сохраняется отдельно. Её можно отключить параметром
`use_supplied_optical_seed=false`. После подгонки падающая ветвь пересчитывается
через общую оптику, тела строятся в SO(3), диаметр 1 мм, полный габарит 10 мм.
Оба варианта проходят существующую проверку тел и адресную полную трассировку.
Выбор сначала минимизирует число конфликтов тел, затем число не прошедших
оптическую проверку путей, затем RMS. Невязка не разрешает принять столкновение.

## Воспроизведённые результаты

При стандартных настройках сохранён условный старт для обеих сторон:

| Сторона / вариант | RMS используемых точек, мм | Конфликты тел | Свободные пути |
| --- | ---: | ---: | ---: |
| WEST, условный старт | 1,615778 | 0 | 77/112 |
| WEST, предложенная подгонка | 0,706053 | 7 | 78/112 |
| EAST, условный старт | 13,256302 | 0 | 112/112 |
| EAST, предложенная подгонка | 11,737822 | 30 | 87/112 |

Подгонка отклонена по физическим проверкам. WEST остаётся `infeasible` из-за
перекрытых путей; EAST — `partial`. EAST RMS по 170 точкам полных линий:
13,047646 мм; 13 согласованных сборок дают 0,659349 мм по 140 точкам.
Три сборки 2.1 / 2.2 / 3.4 имеют RMS 28,203590 / 35,799869 / 28,476982 мм.
Общий RMS выше в таблице: в него входят также одиночные и неполные точки.
В отчёте эти метрики разделены, приведены невязки по каждому зеркалу и сборке.

## Границы реализации

Это интеграция импорта, ограниченного условного уточнения и физических проверок,
а не завершение всей исследовательской программы приложенного задания.
Пока не реализованы новое иерархическое обучение пространственного шаблона,
поиск альтернатив дискретного назначения в ручном режиме, новая оптимизация общей
оптики, bootstrap/posterior и независимый manual-holdout без утечки. Существующий
обычный режим реконструкции сохранён. В нём исправлено сложение угловых и линейных
стоимостей назначения: обе теперь нормированы на соответствующие масштабы.

Для WEST используются 83 установленных соответствия полным наблюдениям;
остальные первичные строки сохраняются, но без соответствия не входят в likelihood.
Точность новых TXT и регистрация других эпох не угадываются.

Отдельно отсутствуют входные данные: подтверждённая геометрия держателей/стержней,
положение перетяжки и метрологические погрешности. Проверки остаются
`not_evaluated`; автоматический приём таких кандидатов запрещён.
Даже 112 свободных путей не подтверждают согласие EAST с первичной геодезией.

## Воспроизведение

```powershell
python tools/refine_manual.py data/manual_refinement/west_manual_corrected_survey.json artifacts/west-manual-native.json --report artifacts/west-manual-report.json
python tools/refine_manual.py data/manual_refinement/east_recovered_centers.json artifacts/east-manual-native.json --report artifacts/east-manual-report.json
python -m unittest discover -s tests -p 'test_*.py'
node --test tests/desktop.test.cjs
node tests/electron_manual.cjs
```

CLI вызывает те же `import_manual` и `refine_manual`, что интерфейс.
`--import-only` сохраняет исходный кандидат, `--options file.json` задаёт сценарий.
Нативный формат остаётся v1: добавлены необязательные проверяемые поля,
старые документы не требуют миграции.
