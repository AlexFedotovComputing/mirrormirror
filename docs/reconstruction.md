# Реконструкция физических микрозеркал

Новый цикл запускается во вкладке «Статическая конфигурация» кнопкой
«Восстановить зеркала». Выбор стороны определяет отдельную
задачу из 112 зеркал; при выборе обеих сторон сохраняются два набора. Для запуска
выберите «Историческая реальная»: её геометрия служит исходной основой, а не
экспериментальным эталоном. В исторической идеальной конфигурации все лучи заданы,
поэтому кнопка недоступна, а запрос оптимизации отклоняется. Если уже есть активная
конфигурация, реконструкция использует её независимо от исторического выбора.
Веер 33° не используется как априорный угловой эталон.

Интерфейс показывает этапы и допускает остановку. Принятая конфигурация хранится
в процессе Electron, поэтому остановка Python не уничтожает её. Только результат
`validated` принимается автоматически; `partial` просматривается и принимается
отдельным явным действием. `infeasible` можно просмотреть и сохранить, но нельзя
принять для рабочей трассировки. Непроверенный импорт остаётся
`legacy_unvalidated`. «Открыть конфигурацию» не повышает достоверность документа.

## Источники и модель

`calibration/observations.py` формирует реестр с SHA-256, адресами ячеек, единицами,
масками и независимыми идентификаторами первоисточников. Исходные XLSX дают
85/17/10 и 83/18/11 записей с двумя/одной/без полных точек. Ни одной сборки 7/7
не требуется. Числа XML в F24/F80 сохраняются; ноль сам по себе не означает
пропуск. TXT, восстановленные таблицы и старые снимки не добавляются к likelihood
как независимые измерения. Конфликт 4_1_3 сохраняется в реестре. Лавсан не
присоединяется к новой модели до независимой проверки соответствий; повтор Z
третьего стержня отмечается отдельно. Старый отчёт лавсана доступен отдельно.

`calibration/empirical.py` обучает семь единичных направлений по неполным сборкам:
сортировка по локальному углу, перебор монотонных подмножеств с возможностью
выброса, согласование общих поворотов в SO(3), робастное сферическое обновление,
несколько стартов. Начальный шаг оценивается по соседним измеренным направлениям;
последующее обновление не требует равного шага. Канонический порядок определяется
направлением веера от −Y к +Y, средним направлением +X и нормалью веера +Z.
Старая строка №7 не обязана быть крайним отсутствующим лучом. Близкие назначения
сохраняются как разные гипотезы; стоимость не называется вероятностью.

`calibration/reconstruction.py` перебирает перестановки стержней, порядок окон и
ориентацию координатного базиса. Геодезия → сцена задаётся обратимым отдельным
преобразованием; det=−1 относится только к смене базиса. Физические тела всегда
имеют det(R)=+1. После жёсткой подгонки сборки разрешаются индивидуальные
отклонения. Каждая сборка использует угловой шаблон, обученный без неё, чтобы
собственные наблюдения не становились вторым независимым prior. Ранг якобиана
данных и регуляризованной задачи сохраняется отдельно.
Среднее индивидуальных переносов обнулено. Из 14 касательных угловых компонент
удалены три общие моды поворота: индивидуальная часть имеет 11 параметров,
ортогональных общему вращению сборки. Численный остаток этого условия сохраняется
в диагностике; регуляризация не заменяет фиксацию этой свободы.

Пространственная раскладка старых зеркал — **неподтверждённый механический prior**.
Она не называется измеренным средним. Центр вдоль выходной прямой, вращение
цилиндра вокруг нормали и смещение попадания по площадке не наблюдаются однозначно.
Рабочая гипотеза характерного луча через центр среза записана в каждом результате.
Метрологический бюджет отсутствует: настройки 0,5/1/2 мм и масштабы регуляризации
являются условными сценариями, а не утверждением о точности установки. Две точки
с нулевой алгебраической невязкой не определяют погрешность измерения.

Шаблоны сторон пока раздельны. Для каждого места сохраняются число независимых
сборок, небольшой PSD-блок ковариации направления, ошибка среднего и
предиктивный разброс отдельного экземпляра. Последний не делится на √N.
Условный масштаб ошибки среднего учитывает число представленных стержней,
а не считает все сборки независимыми: доступно лишь четыре таких кластера.
Результаты с недостаточной наблюдаемостью помечаются `prior_dominated`,
`ambiguous`, `data_and_mechanics` либо `infeasible`.

## Оптика и тела

Сравнение с экспериментом разделено на два независимых отчёта. В основной
программе они доступны после загрузки JSON, реконструкции и расчёта лучей
активной конфигурации. Для исторической конфигурации без реконструкции интерфейс
явно сообщает, что данные подгонки отсутствуют.

`diagnostics.geometric_fit` оценивает **точность подгонки**, а не физическую
проходимость. Все полные двухточечные измерения стороны сопоставляются с выходными
прямыми сохранённых зеркал взаимно-однозначно, без ограничений по номерам и сборкам.
Минимизируется сумма максимальных расстояний двух точек каждой пары до выходного
луча, направленного вперёд. Угол в назначении и отсечении не участвует. Ошибка
каждой пары — худшее из двух расстояний, не средняя ошибка отдельных точек.
Медиана, p90, p95 и максимум считаются **по всем назначенным парам, включая выбросы**;
отдельно показываются количество пар в пределах 1 и 3 мм, пары, выбросы и записи
без назначения. Это согласие с использованными измерениями, не независимая оценка
восстановления отсутствующих лучей.

`diagnostics.trajectory_matching` оценивает **физическую проходимость по сохранённым
адресным трассам**. Это не оценка случайной сетки последнего обычного расчёта.
Из фактически прослеженных выходных путей извлекаются прямолинейные участки:
проход через прозрачный экран продолжает участок, поворот или конец трассы
завершает его. Продолжение за препятствие не допускается. Повторяющиеся начала
ветвей учитываются один раз. Принадлежность к старому номеру луча, зеркала или
сборки не участвует в сопоставлении; стороны ввода проверяются отдельно.

Взаимно-однозначное назначение сначала максимизирует число совпавших измерений,
затем минимизирует геометрическую ошибку. Учитываются обе полностью измеренные
точки; порядок двух точек не задаёт направление распространения. Основной
порог сравнения — 3 мм до каждой точки. Угловая ошибка описательная и не
отсекает пары. Сохранённые старые настройки 1 мм / 6 мрад не восстанавливают
прежний критерий при загрузке. Порог 3 мм — сценарий сравнения, не
метрологический сертификат. Неполные записи перечисляются отдельно и не входят
в знаменатель. Отчёт содержит пары, ошибки, невоспроизведённые измерения с ближайшими
кандидатами и расчётные траектории без пары; последние не обязательно ошибочны,
поскольку измерения неполны. Механические статусы от этого сравнения не меняются.

Оба отчёта пересчитываются из встроенных данных при загрузке старого JSON и входят
в новый результат сохранения; исходный файл автоматически не перезаписывается.

В блоке **«Причины по траекториям»** можно отфильтровать случаи «подгонка есть,
пути нет», все невоспроизведённые, воспроизведённые и неполные измерения. Поиск
работает по идентификаторам измерений, зеркалам, поверхностям и причинам.
Для каждой записи `diagnostics.trajectory_diagnostics` связывает назначенную
подогнанную линию с диагностикой именно её зеркала, отдельно показывая совпавший
или ближайший физический путь. Это геометрическая гипотеза соответствия, а не
доказанная физическая нумерация.

В карточке доступны ошибки обеих точек, последняя поверхность прямолинейного
участка, его длина и координаты конца, последовательность сегментов и расстояния
точек за концом участка. Продолжение линии используется только для объяснения:
если оно совпадает, а конечный участок — нет, различаются перехват другим
микрозеркалом, предел времени, поворот/разрыв и неизвестная причина окончания.
Препятствие **после** обеих измеренных точек не объявляется причиной несовпадения.
Сохранённые причины недоступности входящего пучка, перехвата до среза, неверной
стороны отражения и конфликта взаимно-однозначного назначения также показаны.
Отсутствие сведений в старом JSON не заменяется догадкой о препятствии; новые
расчёты дополнительно сохраняют входящий участок у проверяемого зеркала.
Механические конфликты остаются отдельными ограничениями и не меняют счётчики.

Карточка показывает размеры **сохранённого** тела: для цилиндра Ø1 мм со срезом
45° полные оси эллипса равны 1 и √2 ≈ 1,414 мм. Большая ось эллипса 1,4 мм
сама по себе не означает цилиндр Ø1,4 мм. Показанное смещение центра вдоль луча
является результатом поиска, не установленным допуском крепления. Исходная
компоновка «центр + шесть вокруг» не доказывает свободу независимого перемещения
всех семи тел: численные допуски требуют размеров держателя, зазоров и способа
фиксации. Эта диагностика не меняет размеры и ограничения реконструкции.

В новых контрольных расчётах со скрытым лучом основной показатель также использует
геометрическое сопоставление зафиксированного набора предсказаний без углового
отсечения, а не первый
свободный номер. Там сравниваются предсказанные прямые, не физически прослеженные
пути. Прежние метрики первого слота сохраняются только для совместимости и не
показываются как основная оценка точности.

`engine/bodies.py` задаёт общую геометрию для трассировки, коллизий, сохранения
и отображения:

```text
K = {(x,y,z): x²+y² ≤ r², x ≤ z ≤ h}
r = 0,0005 м; h = 0,0095 м
c = центр отражающего среза
a = R (0,0,1); n = R (1,0,−1)/√2
```

Рабочая конвенция `length_definition=full_extent` означает полный продольный
габарит 10 мм. Альтернатива `cut_center_to_back` с h=10 мм проверяется отдельно.
Чертёж, подтверждающий конвенцию длины, отсутствует. Срез — точный эллипс,
боковая поверхность и основание непрозрачные поглотители по явно указанному
предположению; они не выпускают зеркальные дочерние лучи.

`calibration/physical.py` вычисляет входящую ветвь через источник и всю общую
оптику. Для текущей плоской оптики используются детерминированные пробные лучи
и локальное аффинное поле; каждая рассчитанная стартовая точка независимо
перепроверяется полным трассировщиком. Кеш учитывает оптику и источник.
Недостижимость и неоднозначные ветви сохраняются как диагностика. Константы ±Z
не подставляются. Конвенция нормали — `(d_out-d_in)/|d_out-d_in|`, покрытие
обращено к входящей ветви. При загрузке архивных снимков нормаль и sidedness
согласуются без изменения плоскостей; отдельно воспроизводится случай 26
ошибочных покрытий west_to_east_real. Исправления призм и полного внутреннего
отражения сохранены.

Проверка реальных дочерних лучей запускает адресные лучи от источника в сцену
с **текущими телами**. Она проверяет первый срез, эллипс, сторону, отражение и
дальнейшее экранирование. Визуализация показывает вычисленные сегменты, а не
прямое продолжение сквозь неизвестные оптические поверхности.
Независимая проверка использует полный поиск пересечений и как минимум 48
взаимодействий; обычная трассировка сохраняет выбранный пользователем лимит
и явно сообщает о незавершённых лучах. Отбор по точным ограничивающим объёмам
тел проверен сравнением с полным поиском и не отключает поглощение телами
после первого отражения.

Опорные точки истинного скошенного цилиндра используются в GJK. Для отделения
касания от пересечения добавлен независимо проверяемый сертификат общей
внутренней сферы; отрицательный результат оптимизатора сам по себе не доказывает
разделения. Сертификат разделяющей плоскости пересчитывается аналитическими
опорными функциями. Это развитие схемы расстояния из
[Gilbert, Johnson, Keerthi, 1988](https://graphics.stanford.edu/courses/cs448b-00-winter/papers/gilbert.pdf),
а не реализация EPA. Численная точность и технологический зазор задаются раздельно.
Проверяются все потенциально близкие пары, включая соседние сборки.

Коллизии допускают ограниченную подстройку ненаблюдаемого вращения тела вокруг
нормали и последующее совместное смещение центра **вдоль подогнанной выходной
прямой**. Последнее не меняет измеренную линию. В текущем условном сценарии
`axial_center_sigma_m=0.01`, предел — 3σ; это открытые настройки, а не размер,
подтверждённый чертежом. Ограничиваются доступный входящий пучок и точные
сертификаты разделения. Входящее поле и отражения пересчитываются после движения.
Условия разделения жёсткие, решение перепроверяется независимо. Неудача
сохраняется, а не скрывается
малой штрафной добавкой. Области держателей и подтверждённая перетяжка отсутствуют:
`rod_containment`, `holder_collisions`, `waist_side` остаются `not_evaluated`.
Радиус 30 мм из lasertest не подставляется как радиус держателя.

## Независимая проверка и границы результата

В `calibration/validation.py` основная проверка скрывает исходную траекторию и
исключает всю целевую сборку из обучения углового шаблона. Копии того же
первоисточника также исключаются. Исторические восстановленные центры не являются
независимой механикой: поэтому первичная проверка углов и реальных XY-сечений
работает в геодезической системе, используя только видимые исходные точки.
Это условный тест веера с общей точкой, **не сертификация всей физической
реконструкции на скрытых данных**. Независимая проверка полных тел требует внешней
механической геометрии и регистрации. Старый геометрический результат допускается
лишь как явно зависимый исторический ориентир.

Метрики содержат медиану, 90-й процентиль, максимум, отказы, число альтернатив
и эмпирическое покрытие условных интервалов. Ошибка ближайшего элемента множества
гипотез приводится отдельно от ошибки заранее выбранного луча. Она не означает
однозначного восстановления. Скрытие целой сборки — отдельный эксперимент,
который не подменяется скрытием одного луча.

Альтернативы нумерации сохраняются как разные оптические гипотезы; наличие такой
гипотезы не означает отдельную проверенную 3D-конфигурацию. Полная проверка тел
и последующего экранирования относится к выбранному физическому кандидату.

Полный физический успех не обещается: противоречащие данные, пересечения,
экранование или отсутствующие механические параметры остаются в документе.
Оптимизатор `success=True` не изменяет статус независимых проверок.

## Сохранение, загрузка и импорт

`state.py` сохраняет формат `mirrorlab.physical-configuration`, `schema_version=1`.
В `datasets[direction]` находятся все 112 поз, общая оптика и источник,
параметры тел, нормализованные исходные наблюдения, SHA-256, преобразования,
шаблон, назначения и альтернативы, траектории, неопределённости и диагностика.
Документ содержит базовый commit и хеши фактических Python-исходников; локальные
изменения тем самым различаются даже без нового коммита. Оптический хеш устойчив
к потере различия `1.0`/`1` при обмене с JavaScript. Большие целочисленные
идентификаторы/временные метки записываются строками.
Обычные настройки трассировки также фиксируются: для ранних документов v1
пропущенные параметры разворачиваются из констант версии формата, а не из
будущих defaults трассировщика (`surface_epsilon=1e−7 м`, `min_power=1e−18`).
Это отдельные величины от допуска проверки столкновений.

Сохранение выполняется во временный файл рядом с целевым, с `fsync` и атомарной
заменой. Загрузка полностью проверяет версию, конечность, размеры, уникальность,
ссылки назначений, PSD-ковариации, единицы, SO(3), маски и хеш оптики до изменения
активной конфигурации. Исходные файлы проекта для повторной трассировки не нужны.
Неизвестная версия отклоняется. Предыдущего нативного физического формата не было:
старые статические JSON мигрируют через отдельное действие импорта; Plotly-отчёт
или список лучей не объявляется физической конфигурацией.

`legacy_import.py` поддерживает:

- Полные экспортированные статические JSON с явным направлением.
- Real-дельты с точной указанной базой. Для четырёх экспортов проверенной базы
  e57e447 встроен манифест хешей; для иных дельт нужен `base_sha256` или
  `base_configuration_sha256`. Отсутствующая/неподтверждённая база даёт частичный
  импорт без общей оптики, а не подстановку текущей ideal.
- TXT из четырёх углов площадки, из центра/нормали или четырёх углов с
  центром/нормалью; значения в метрах. Физическую сторону и систему координат
  пользователь указывает явно. Поворот вокруг нормали остаётся prior.
- Табличные уравнения лучей — только производные наблюдения, без выдуманной
  физической конфигурации.
- ZIP с однозначными распознаваемыми данными, включая упаковку Optimis_code-main.
  Python-код не выполняется, архив на диск не извлекается, опасные пути и
  неоднозначные таблицы отклоняются.

`service.py` строит сцену, трассирует и сохраняет одно активное состояние.
Диагностический кандидат — результат для просмотра и сравнения; он не меняет
конфигурацию следующей трассировки. «Принять для расчётов» выбирает его для следующих
расчётов, сохраняя исходный статус проверок (`partial`, `legacy_unvalidated`).
Проверенный результат (`validated`) и допустимая нативная загрузка принимаются
автоматически. При `infeasible` или отсутствии общей оптики кнопка остаётся
видимой, но недоступной; рядом указана причина. Сохранение кандидата не означает
его принятие.

Основная сцена сохраняет последний результат трассировки и добавляет геометрию
и траектории реконструкции, а также восстановленные по измерениям лучи отдельными
слоями. Повторное построение заменяет базовый слой, сохраняя непринятого кандидата
для сравнения. Повторная реконструкция заменяет слой кандидата без накопления
дубликатов. В раскрываемой панели «Слои и сравнение» над графиком можно независимо выбирать стороны
ввода WEST/EAST, наборы данных и типы объектов: лучи трассировки, реконструированные
лучи, оптику, лучи и точки измерений, попадания на экраны, лазеры и общую границу.
Фильтры применяются совместно, сохраняются при новом расчёте и не меняют камеру.
Сторона и тип объекта передаются в метаданных каждого слоя; подписи легенды
не используются для определения принадлежности. Шкала интенсивности скрывается
вместе с соответствующими лучами.
Легенда по умолчанию скрыта и включается кнопкой «Легенда». При отключении всех
слоёв доступно действие «Показать все слои». Отчёты трассировки и измерений
сохраняются при просмотре кандидата; переходы над сценой ведут к доступным отчётам.
Источник следующей трассировки указан в панели параметров при наличии кандидата
или принятой конфигурации. Изменение параметров помечает показанную сцену как
предыдущий результат, не запуская расчёт автоматически.
Совмещение разрешено только в общей геодезической системе. При несовместимых
системах показана реконструкция, а отключение её слоя возвращает построенную сцену.
Траектории показаны пунктиром, измеренные направления — точечным пунктиром в
пределах измеренных точек. Для направления без рассчитанного пути отображается
только маркер начала с подписью «путь не рассчитан».

`worker.py` передаёт `progress/result/error` с `job_id` и версией конфигурации;
`desktop/configuration-state.cjs` не принимает устаревший результат. Проценты
появляются только для этапов с определённым числом сборок/проверок.

## Воспроизведение

Основной сценарий выполняется кнопками приложения. Для автоматизации тот же цикл:

```powershell
python tools/reconstruct_configurations.py --direction both --output artifacts/reconstruction/both.json
python -m unittest discover -s tests -p 'test_*.py' -v
npm run test:desktop
npm run test:ui
$env:MIRRORLAB_EXTENDED_UI = '1'
npm run test:ui
```

`--skip-holdout` нужен только для быстрой диагностики; отсутствие проверки
записывается в результат. Данные не перезаписываются. Сохранённые примеры и
численные итоги конкретного прогона перечислены в [validation.md](validation.md).
