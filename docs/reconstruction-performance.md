# Ускорение реконструкции без изменения численной задачи

Исходная версия для сравнения: `5aac989`. Проверяется обычная реконструкция
и ручное уточнение, отдельно WEST (`east_to_west`) и EAST (`west_to_east`).

## Результат замера

Windows, Python 3.11.9, NumPy 2.4.4, SciPy 1.17.1; полная реконструкция со
стандартным holdout, по одному последовательному запуску до и после:

| Сторона | До, с | После, с | Ускорение |
| --- | ---: | ---: | ---: |
| WEST | 108,988 | 33,514 | 3,25× |
| EAST | 117,006 | 41,615 | 2,81× |

Сравнение полных снимков обеих сторон и обоих режимов охватывает 358 422
численных значения. Максимальное абсолютное отличие равно **0**; назначения,
альтернативы, траектории и статусы также совпали. Отличаются только служебные
отпечатки `field_hash`, причина описана ниже. Полная реконструкция WEST осталась
`partial`, EAST — `infeasible`; ручная WEST — `infeasible`, EAST — `partial`.
Ускорение не превращает исходные физические противоречия в успешный результат.

Проверки: 116 Python-тестов и 15 тестов desktop-протокола прошли.
Результаты сравнения: `artifacts/performance/comparison.json`; времена и полные
снимки: `artifacts/performance/{before,after}/`.

Ручное уточнение дополнительно измерено по три раза для старой и новой версии,
с холодными кешами и чередованием порядка. Медианы WEST: 3,955 → 3,706 с;
EAST: 3,947 → 3,693 с. Наблюдаемый выигрыш около 6%; разброс WEST заметен,
поэтому кратное ускорение этого режима не заявляется. Протокол:
`artifacts/performance/manual-repeated.json`.

Во время дополнительного замера параллельно были добавлены диагностические поля
`target_surface` и `incident_segment`, не относящиеся к ускорению. Только в этом
дополнительном сравнении они исключены вместе с `field_hash`; остальные данные
совпали точно. Основное сравнение четырёх полных снимков выше выполнено до этого
добавления и исключает только `field_hash`. После добавления повторно прошли
четыре проверки кеша и полных физических отчётов на реальных данных.

## Изменения

В `empirical.assign_fan` индексы подмножеств и маски исключения предвычисляются
и хранятся в ограниченном кеше. Все прежние гипотезы оцениваются пакетной SVD;
потенциально возвращаемые гипотезы пересчитываются прежними скалярными операциями.
Защитная полоса предварительного отбора учитывает обусловленность. При вырождении
задачи правильного вращения используется полный скалярный пересчёт. Итоговые
порог неоднозначности, сортировка и альтернативы не меняются.

В `physical` повторные просмотры списка сегментов заменены индексами по родителю
и оптической ветви. Порядок записей и разрешение равных кандидатов сохранены.
Проверенное входящее поле повторно используется только при точном совпадении
общей оптики, источника, времени, настроек трассировки, эффективного лимита
взаимодействий, координат и порядка ID. Кеш ограничен восемью записями и выдаёт
глубокие копии. Он не хранит результаты полной проверки сцены с телами:
перекрытия и отражения проверяются при каждом вызове.

Решатели, регуляризация, число стартов и итераций, набор гипотез, holdout,
механические допуски и полный перебор физических поверхностей сохранены.
Оптимизация SLSQP, распараллеливание и перенос вычислений на GPU не входят в
это изменение.

## Проверка эквивалентности

`test_empirical_optimization.py` содержит замороженную прежнюю реализацию
сопоставления и требует точного равенства результатов. Проверяются 3–7 лучей,
выбросы, перестановки, равные и почти равные оценки, соседние значения порога
через `nextafter`, вырожденные вращения и полное обучение шаблонов обеих сторон.

`test_physical_optimization.py` проверяет порядок индексов, изменение входов,
изоляцию изменяемых результатов, ограничение размера кеша и точное совпадение
полных отчётов для реальных WEST/EAST при прежних сканах, новых индексах и
повторном использовании поля. Отдельно проверяется, что полная трассировка
с телами выполняется и при попадании в кеш.

Полные снимки до/после записываются в `artifacts/performance`. Сравнение проходит
по всему дереву: тела, траектории, невязки, назначения, альтернативы, ранги,
физические проверки, holdout и статусы. По умолчанию допустимое численное отличие
равно нулю. Исключается только `field_hash`: его новое значение учитывает
эффективный лимит взаимодействий, ранее отсутствовавший в ключе кеша.

## Воспроизведение

```powershell
# До изменений, затем после изменений в одном и том же окружении:
python tools/benchmark_reconstruction.py artifacts/performance/before
python tools/benchmark_reconstruction.py artifacts/performance/after
python tools/compare_reconstruction_benchmarks.py artifacts/performance/before artifacts/performance/after --output artifacts/performance/comparison.json
python -m unittest discover -s tests -p 'test_*.py'
```

Каждый полный расчёт использует стандартные настройки, включая holdout;
ручное уточнение — стандартный сценарий пакета. Импорт и запись JSON находятся
вне таймера. Кеши физических полей очищаются перед каждым замером. Запуски
выполняются последовательно, без одновременных тестов или другого benchmark.
Время одного запуска характеризует это рабочее место, а не гарантированную
производительность на любом компьютере.
