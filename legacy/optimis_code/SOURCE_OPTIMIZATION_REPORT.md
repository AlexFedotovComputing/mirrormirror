# Этап 2: оптимизация генерации исходного гауссова пучка

Дата: 2026-09-24.

## Изменение

Историческая `emit_initial_rays()` сначала вызывала `source.emit()` при
`radial_positions=55`, затем увеличивала число колец и полностью перестраивала
пучок до достижения 20 000 лучей. Последний вызов при `radial_positions=82`
создавал 20 419 лучей, после чего прежний `keep_idx` оставлял ровно 20 000.

Количество лучей для `n` радиальных позиций известно без создания массивов:

```text
N(n) = 1 + sum(6*k, k=1..n)
     = 1 + 3*n*(n+1)
```

Новая реализация дешёво увеличивает только Python-параметр
`source.radial_positions`, пока `N(n) < target_count`, после чего вызывает прежний
`GaussianBeamSource.emit()` ровно один раз. Если результат больше target, без
изменений используется прежнее выражение:

```python
keep_idx = floor(linspace(0, rays.n_rays, target_count, endpoint=False))
```

Таким образом сохранены:

- начальное значение `radial_positions` конкретного source;
- первый минимальный размер кольцевой сетки, достаточный для target;
- мутация `source.radial_positions` до выбранного значения;
- порядок генерации колец и лучей внутри `GaussianBeamSource.emit()`;
- алгоритм детерминированного trim;
- все физические значения итоговых лучей.

## Эталон и корректность

До изменения сохранён `source_generation_baseline.json` для 20 000 лучей:

- selected `radial_positions`: 82;
- размер до trim: 20 419;
- итоговый размер: 20 000;
- total power: 11 295 153,303177167 W;
- SHA-256 каждого из 12 массивов `RayBundle`.

`test_source_generation.py` содержит замороженную старую реализацию и проверяет
побитовое равенство новой функции для:

```text
1, 9240, 9241, 9242, 9577, 9578, 20000 лучей
```

Значения 9 241 и 9 577 являются точными границами `N(55)` и `N(56)`.
Сравниваются:

- position и direction;
- power и intensity;
- polarization;
- wavelength и refractive index;
- time;
- ray_id, parent_id и depth;
- bundle_reflected;
- выбранное `source.radial_positions`.

Отдельный тест пересчитывает SHA-256 новой 20k-генерации и сравнивает их с
сохранённым baseline. Все NumPy-проверки проходят побитово, без допуска.

```text
Ran 4 tests in 6.380s
OK (skipped=1)
```

Пропущен только CuPy-тест: пакет CuPy и CUDA runtime отсутствуют на машине.
Сам тест автоматически выполнится в CUDA-окружении.

Полный differential trace с 20 000 лучей также прошёл. Exhaustive и
оптимизированный broad phase дали побитово одинаковые segments, detector hits,
detector power summary и дерево вторичных лучей.

использованы 20 000 лучей, 20 взаимодействий, 50 ns и все 184 поверхности.

## NumPy/CuPy

Предварительный подсчёт использует только Python `int` и не обращается к backend.
После выбора `radial_positions` выполняется один обычный `source.emit()`. Для trim
сохраняется прежний `rays.xp.asarray(keep_idx)`. Дополнительных GPU→CPU передач,
синхронизаций или backend kernels не добавлено.

## Неизменённые части

- консервативный broad phase и `use_broad_phase=False` сохранены;
- `GaussianBeamSource.emit()` не изменён;
- физические параметры и геометрия не изменены;
- CSV, Plotly и интерактивный сервер не изменены;
- прямая генерация только выбранных 20 000 лучей не реализовывалась: простой
  однократный `emit()` уже устраняет 95% работы и сохраняет минимальный риск.
